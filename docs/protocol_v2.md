# Protocol v2 — Specification-Grounded Proactivity Decision Research

Date: 2026-08-14

Primary branch: `research/proactivity-specification-v2`

## Why the protocol changed

Protocol v1 asked whether a six-way intervention taxonomy could be supported by genuinely independent human annotation. Its historical Gate-B verdict remains `BLOCKED_BY_INDEPENDENT_ANNOTATION`, and its evidence-weighted completion remains 25% under the v1 weighting. That result is preserved rather than reinterpreted.

Protocol v2 changes the scientific claim instead of fabricating or bypassing missing human evidence. The primary research target is now **specification compliance**: whether a deterministic, auditable decision layer can map an explicit structured state to one of six intervention-control modes while satisfying a frozen research policy and machine-checkable invariants.

## Current primary research question

> Can a deterministic, auditable proactivity decision layer map explicitly represented state concerning permission, timing, information sufficiency, risk, reversibility, action side effects, intervention need, and related observable conditions to a policy-compliant intervention mode, while satisfying a frozen formal specification and remaining consistent under counterfactual and temporal changes?

## Primary evidence chain

```text
structured state
    -> frozen formal specification
    -> deterministic oracle
    -> expected intervention mode
    -> rule/prohibition trace
    -> machine-verifiable evidence
```

Natural-language context is not normative ground truth in Protocol v2. A later raw-context track may test state extraction, language variation, and robustness, but the oracle must operate on the generator-known formal state.

## Intervention modes

The protocol retains six discrete modes:

- `IGNORE`
- `WAIT`
- `SUGGEST`
- `NOTIFY`
- `ASK`
- `ACT`

They are **not** assumed to form a universally valid scalar intensity ordering. In particular, `ASK` versus `NOTIFY`, and `IGNORE` versus `WAIT`, have different permission/timing semantics rather than a universal greater-than relationship.

## Ground truth

Protocol v1 primary ground truth: independent human first-pass judgments, followed by reliability analysis.

Protocol v2 primary ground truth: a frozen structured state plus the frozen versioned specification evaluated by the deterministic reference oracle. Gold decisions must not be separately handwritten and must not be generated by an LLM judge.

## Claim boundary

Protocol v2 may support claims about specification compliance, deterministic intervention-control decisions, permission-sensitive autonomy, constraint satisfaction, counterfactual and temporal consistency, traceability, invariant satisfaction, and reproducibility.

It does not establish human preference alignment, user satisfaction, universal correctness, social acceptability, psychological validity, or ecological validity outside the modeled conditions. The specification is a research policy, not universal human truth.

## Protocol v1 evidence retained

The repository preserves:

- historical human annotation packet tooling;
- immutable annotation archive tooling;
- agreement and Cohen's kappa utilities;
- the `development_v1` generator and SHA evidence;
- historical leakage failures and CI incidents;
- the v1 `BLOCKED_BY_INDEPENDENT_ANNOTATION` verdict.

These are Protocol-v1 / optional future human-validation artifacts. They no longer block the primary v2 gate sequence.

## Gate architecture

1. **Gate A — Scope / claim boundary / prior-art positioning**
2. **Gate B — Formal specification validity**
3. **Gate C — Oracle and benchmark validity**
4. **Gate D — Baseline integrity**
5. **Gate E — PDA candidate evidence**
6. **Gate F — Protected / OOD validation**
7. **Gate G — Robustness, adversarial, and invariant stress testing**
8. **Gate H — Ablation, reproducibility, independent reproduction, and final claim audit**

No Gate-C baseline or candidate optimization is authorized by the Protocol-v2 migration itself.

## Gate-B pass contract

Protocol-v2 Gate B requires all of the following before PASS:

- valid, finite state schema;
- frozen action semantics;
- deterministic oracle over the tested bounded state space;
- no unresolved equal-priority action conflicts;
- no valid-state fallthrough;
- zero mandatory invariant violations;
- invalid states fail closed;
- metadata/domain identifiers do not control oracle decisions;
- complete decision traces;
- counterfactual policy tests pass;
- temporal-rule tests pass;
- state-space coverage evidence exists;
- required CI is green on Python 3.10, 3.11, and 3.12;
- no material unresolved specification ambiguity.

If Gate B passes, the authorized stop state is:

```text
GATE B — PASS
READY FOR GATE C
DO NOT START GATE C
```

## No-human dependency statement

The primary Protocol-v2 A–H research sequence is designed so that its required evidence can be generated and audited without human annotation or a human study. Human validation can be added later as a separate external-validity or preference-alignment study, but it is not a prerequisite for the primary specification-grounded claims.
